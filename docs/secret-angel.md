# 비밀 천사 운영 및 배포 안내

> **현재 접속 방식:** 관리자에서 개인 초대 링크를 발급하고 참가자는 이름 확인 후 “이 기기로 참여하기”를 누릅니다. PIN/참여코드 수동 입력은 종료되었습니다. 링크는 7일·1회 사용, 기기 자동 접속은 같은 브라우저에서 90일입니다. 아래 이전 PIN 방식의 기록은 개발 이력이며, 현재 운영 절차는 문서 마지막의 “개인 초대 링크와 기기 등록” 절을 따릅니다.

> 후속 운영 반영: 사용자가 실제 서비스 배포를 승인했습니다. Vercel `kyuky920s-projects/ghchurch` 운영 DB는 `nanylleoxdtynibznfft`입니다. 기존 로컬/README 예제의 `khzweuawuyrqohgjdzsn`과 다릅니다. 운영 DB에 아래 migration을 SQL Editor로 적용했고 관리자 환경변수를 설정했습니다. 아래 “검증 결과”의 미배포 기록은 최초 개발 검증 당시의 기록이며, 실제 앱 공개 상태는 최신 Vercel 배포로 확인합니다.

## 현재 구현

관리자 기능은 `/leader?tab=secret-angel`의 **마니또 관리** 탭에서만 제공합니다. `/leader`의 마니또 관리 메뉴로 접근할 수 있습니다. `/secret_angel`은 참가자 전용이며 관리자 로그인·운영 기능이 없습니다. 마니또 관리는 비밀번호 없이 누구나 조회·변경할 수 있는 공개 화면입니다. 참가자는 개인 초대 링크로 기기를 등록하고 이후 자동 접속합니다.

- 기존 Next.js 14 Pages Router, React 18, Supabase service role API 구조를 유지했습니다. `/cell`에 `/secret_angel` 진입 링크를 추가했습니다.
- 기존 셀의 이름·기기 ID 로그인은 마니또 인증으로 사용하지 않습니다. 기존 `members`, `app_members`, 셀모임 테이블은 수정하지 않습니다.
- 관리자: 별도 인증 없이 리더 도구에서 모임 조회·생성·배정·초대 링크 발급·공개·삭제를 사용할 수 있습니다.
- 모임: 관리자가 입력한 명단으로 인원수에 맞춰 생성합니다(최소 2명, 별도 최대 인원 제한 없음). 동명이인은 `김소망A`, `김소망B`처럼 구분합니다. 참가자별 무작위 일회용 초대 링크를 개별 전달합니다.
- 참가자: 개인 초대 링크에서 이름 확인 후 기기 등록. 다음부터 같은 브라우저에서 자동 접속합니다. 초대/기기 토큰은 각각 256비트 무작위 값이며 SHA-256 해시만 저장합니다.
- 관리자 초대 링크 재발급은 해당 참가자의 기존 기기와 이전 링크를 즉시 무효화합니다. 링크 목록은 발급 화면에 한 번만 표시됩니다. 시작 후에도 새 기기를 등록할 수 있습니다.
- 전원 등록 후 관리자 확정으로 한 번만 비밀 배정합니다. 암호학적 난수로 섞은 순환 배정이므로 자기 배정·중복이 없으며, 3명 이상이면 상호 맞교환도 없습니다. 2명은 서로에게 배정됩니다. 배정 재추첨과 시작 후 명단 변경은 지원하지 않습니다. 관리자는 접힌 전용 배정표를 볼 수 있습니다.
- 시작일은 현재부터 30일 이내로 예약할 수 있습니다. 시작 시각부터 7일마다 다음 주가 열립니다. 활동은 정확히 56일 동안이며 일일 제한은 한국 시각(UTC+9) 자정에 초기화됩니다. 시작 시각 입력은 기기 현지 시각을 UTC로 변환해 전송합니다. 표시 시각은 한국 시각입니다.

| 기능 | 열림 | 제한 및 공개 범위 |
| --- | --- | --- |
| 주차별 미션 | 1~8주차 순서대로 | 주차당 한 번 10P, 지난 열린 주차 완료 가능, 포인트는 본인만 확인 |
| 기도 제목 | 1주차 | 매주 1개, 본인과 본인을 돌보는 천사만 열람 |
| 기도 응답/감사 | 1주차 | 본인이 기록, 천사가 함께 열람. 천사는 배정된 친구에게 기도 표시 가능 |
| 하트 | 1주차 | 배정된 친구에게 하루 1개. 받는 사람에게 발신자 미공개 |
| 익명 양방향 편지 | 2주차 | 내 마니또 / 나의 비밀 천사 대화방 분리, 방마다 하루 5개, 500자 |
| 의심하기 | 3주차 | 매주 1회, 자신 제외 누구나 선택. 받는 사람에게 의심한 사람의 이름 공개 |
| 의심 답변 | 3주차 | 받은 의심당 준비된 문구 1회. 정답 여부는 계산·전달하지 않음 |
| 정체 공개 | 56일 경과 후 | 관리자가 공개 확정하면 전체 배정표 공개, 이후 활동 종료 |

주차 2 미션에는 익명 편지가 포함됩니다. 미션은 본인 완료 확인 방식이며 편지를 작성했다고 자동 점수가 부여되지는 않습니다. 참가자 기도·편지는 관리자 화면에서도 조회하지 않습니다. 다만 DB service role 접근 권한을 가진 운영자는 DB 원본을 볼 수 있으므로 종단간 암호화 서비스는 아닙니다. 참가자가 직접 편지 본문에 정체를 쓰는 것은 차단하지 않습니다.

## 데이터와 보안

새 테이블은 `secret_angel_seasons`, `secret_angel_sessions`, `secret_angel_limits` 세 개입니다. 소규모 모임 운영에 맞게 모임 상태를 단일 private JSONB 행에 저장합니다. 변경마다 버전 조건으로 원자적 갱신하고 충돌 시 최신 상태로 재검증합니다. 중복 포인트·하트·의심과 동시 등록을 같은 방식으로 방지합니다. 규모가 커질 경우 활동별 테이블로 분리가 필요합니다.

- 세 테이블 모두 RLS 활성화, `PUBLIC`/`anon`/`authenticated` 권한 회수, service role만 접근.
- rate limit RPC도 일반 사용자 실행 권한 회수. DB 기반 원자적 제한이므로 여러 Vercel 인스턴스에서 공유됩니다. 로그인 계정당 15분 8회, 전체 인증 15분 300회, 인증 세션당 분당 120회입니다. 성공한 로그인도 횟수에 포함되며 429일 때 제한 창 이후 재시도합니다.
- 브라우저는 service key를 받지 않습니다. API가 등록 기기의 모임·참가자·기기 해시와 변경 버전을 확인하고 필요한 데이터만 반환합니다. 클라이언트가 보낸 관리자 플래그/발신자/수신자를 권한으로 사용하지 않습니다.
- 쿠키: HttpOnly, SameSite=Strict, 프로덕션 Secure, `/api/secret-angel` 경로, 90일 만료. 기기 해제 시 쿠키와 DB 기기 해시를 무효화합니다. 관리 화면은 쿠키 없이 공개 접근합니다.
- 변경 API는 JSON과 동일 출처를 확인하고, 모든 응답에 `private, no-store`를 지정합니다. 기도·편지·PIN·참여코드를 브라우저 저장소에 저장하지 않습니다. 탭 복원을 위해 모임 코드만 sessionStorage에 보관합니다.
- 공개 시점까지 천사 이름, 전체 배정표, 다른 사람의 콘텐츠와 PIN 해시는 참가자 응답에 포함하지 않습니다. 인증된 같은 모임 참가자는 의심할 대상을 고르기 위해 참가자 이름 명단을 봅니다.
- 기본 API 본문 한도는 16KB. 기도·편지·응답은 500자, 이름 30자, 모임명 60자 제한입니다.

Supabase 권한 설계 참고: [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security), [Database functions](https://supabase.com/docs/guides/database/functions).

## 검증 결과 (2026-10-25)

- `npm run test:secret-angel`: 22개 통과. 등록·복구, 배정 불변식 100회, 잠금 경계, 개인정보 범위, 양방향 편지 분리, 의심 제한, 로그인·세션·계정 제한·동시 요청을 검증했습니다.
- `npm run build`: 전체 라우트 프로덕션 빌드 통과. 테스트용 Supabase URL/key로 빌드했고 운영 DB에는 연결하지 않았습니다. 기존 Browserslist 데이터 갱신 안내와 외부 Google Fonts 다운로드 실패 경고가 있으며 빌드 실패는 아닙니다.
- 임시 PGlite PostgreSQL에서 마이그레이션과 `supabase/tests/secret_angel.sql` 실행 통과. 일반 사용자 테이블/RPC 차단, service role 접근, 버전 충돌, 제한 RPC, 세션 연쇄 삭제와 롤백 확인. 실제 Supabase PostgREST와 배포 환경 연결 검증은 별도 staging 확인이 필요합니다.
- 실제 Chrome 390px 모바일 뷰에서 운영 DB와 격리한 API 테스트 어댑터 사용: 관리자 모임 생성 → 코드 등록 → 배정 → 미션/포인트 → 하트 → 기도/응답 → 편지 채널 분리 → 의심 → 새로고침 → 로그아웃 통과. 가로 넘침과 페이지 JavaScript 오류 없음.
- 이 기기의 기본 Homebrew Node는 `libsimdjson.29.dylib` 누락으로 실행되지 않습니다. 검증은 Codex 번들 Node v24.22.1로 수행했습니다. 일반 로컬 실행 전 Node 설치를 복구하거나 정상적인 Node 런타임을 PATH에 지정하세요.
- 운영 DB 마이그레이션, 원격 push, 프로덕션 배포는 실행하지 않았습니다.

## 배포 절차 (미실행)

1. 기존 사용자의 변경과 이번 파일을 함께 검토합니다. DB 백업/복구 수단이 있는 staging Supabase를 준비합니다. 운영 DB를 로컬 검증 DB로 쓰지 마세요.
2. 정상적인 Node 환경에서 기존 lockfile 기준 `npm ci` 후 `npm run test:secret-angel`을 실행합니다.
3. staging DB에 `supabase/migrations/202610250001_secret_angel.sql`을 적용합니다. 프로젝트의 migration 이력을 먼저 확인한 뒤 Supabase CLI 또는 SQL Editor를 사용합니다. 다른 migration을 확인 없이 함께 밀어 넣지 마세요.
4. staging DB에서 `supabase/tests/secret_angel.sql`을 실행합니다. 테스트 데이터는 transaction rollback으로 제거됩니다. SQL Editor의 DB 관리자 권한으로 실행해야 역할 전환을 검사할 수 있습니다.
5. 서버 환경변수를 설정합니다:
   - `SUPABASE_URL`: staging/대상 DB URL
   - `SUPABASE_SERVICE_KEY`: 해당 DB의 서버 전용 service role key
   - `NEXT_PUBLIC_APP_URL`: 실제 접속할 URL의 origin과 일치해야 합니다. 로컬은 `http://localhost:3000`, preview는 해당 preview origin, 운영은 `https://ghchurch.vercel.app`. 경로는 제외합니다. 이 값이 다른 origin이면 변경 요청이 거절됩니다.
6. `npm run build` 후 preview에 반영합니다. `/cell` 링크, 서로 다른 인원의 테스트 모임 생성·개인 초대 링크 등록·자동 접속·기기 재등록·시작을 확인합니다. 두 명 이상의 세션으로 배정된 친구와 천사 간 편지/기도를 확인하고, 제3자 접근이 차단되는지 점검합니다. 주차를 빠르게 확인하려면 격리된 테스트 DB의 테스트 모임 시작 시각만 조정합니다.
7. 사용자가 프로덕션 반영을 요청한 뒤에만 운영 DB에 migration 적용 → 운영 환경변수 설정 → 앱 배포 순서로 진행합니다. 현재 작업에는 이 단계 실행이 포함되지 않았습니다.
8. 담당 리더가 `/leader?tab=secret-angel`의 마니또 관리 탭을 열어 모임 생성 → 개인 코드 개별 전달 → 전원 등록 확인 → 시작 확정을 합니다. 관리 화면은 누구나 사용할 수 있으며 배정표와 참가자 명단도 공개됩니다.

운영에는 별도 cron 없이 조회 시 서버 시각으로 주차가 자동 계산됩니다. 시작 시각 이후에는 재추첨·시간 변경을 제공하지 않습니다. 56일이 지나면 관리자가 최종 공개를 확정합니다. 코드 재발급과 공개 버튼은 추가 확인을 거치고, 영구 삭제는 정확한 모임 코드를 입력해야 합니다.

## 보관과 삭제

기본 자동 보관 만료 정책은 없습니다. 행사 종료 30일 후 모임을 삭제하는 운영 정책을 권장합니다. 모임 관리자 화면의 삭제 기능을 실행하면 이름·PIN 해시·배정·기도·편지·하트·의심이 있는 모임 행과 관련 참가자 세션을 삭제합니다. DB 백업 보관 정책에는 별도 적용이 필요합니다. 이 기간을 참가자에게 사전 안내하세요.

만료된 인증/제한 행은 정기 점검 시 아래와 같이 삭제할 수 있습니다. SQL은 운영자가 필요한 환경에 직접 적용합니다.

```sql
delete from public.secret_angel_sessions where expires_at < now();
delete from public.secret_angel_limits where resets_at < now();
```

우선 기존 앱 버전으로 되돌려 새 경로와 API를 내립니다. 기존 셀 테이블은 수정하지 않았으므로 기존 `/cell`은 유지됩니다. 모임 데이터 보존이 필요하면 새 테이블을 그대로 둡니다. 완전 제거가 승인된 경우에만 백업 후 RPC와 새 테이블 세 개를 삭제합니다. 운영 데이터가 들어간 테이블을 배포 롤백과 동시에 자동 삭제하지 마세요.

## 리더 도구 통합 검증

관리자 API와 참가자 API의 교차 접근 차단, 과거 관리자 쿠키 차단, 같은 브라우저의 독립 세션, 관리자 Secure 쿠키 검사를 추가했습니다. 전체 테스트 25개 통과. 기존 세션에서 관리자 기능을 썼다면 리더 도구에서 한 번 다시 로그인해야 합니다. DB와 관리자 비밀번호의 변경은 필요 없습니다.

리더 메뉴는 말씀 자료·셀 조 편성·회원 관리·운영 대시보드·마니또 관리 5개로 정리했습니다. 중복되는 상단 마니또 바로가기 링크와 출석 관리·딕싯 메뉴는 제거했습니다.

관리자 비밀번호를 변경하면 운영 환경변수와 배포를 갱신한 후 기존 관리자 세션을 취소합니다. 참가자 PIN과 참가자 세션은 변경하지 않습니다.

## 가상 참가자 테스트 모임

운영자가 테스트 목적으로 명시적으로 준비한 `testMode: true` 모임만 리더 도구에 테스트 진행 버튼이 표시됩니다. 다음 주차·3주차·8주 종료 이동과 활동 기록 초기화가 가능하며, 일반 모임 생성으로는 이 표시를 켤 수 없습니다. 서버에서 관리 API 경로와 테스트 모임 표시를 검사합니다. 관리 API는 공개되어 있습니다. 참가자는 자신의 테스트 모임 표시만 보며 주차를 변경할 수 없습니다. 초기화는 배정과 PIN을 보존하고 미션·기도·하트·편지·의심을 지운 뒤 1주차로 돌아갑니다. 일반 모임의 8주 제한은 유지됩니다.

## 2026-10-27 공개 관리 전환

사용자 요청으로 관리자 비밀번호 입력과 관리자 로그인·로그아웃·세션 발급을 제거했습니다. 관리 API는 비밀번호·쿠키 없이 접근할 수 있으며 이름 명단과 배정표 조회, 모임 생성·시작·PIN 재발급·최종 공개·삭제를 누구나 실행할 수 있습니다. 기도·편지 원문은 기존과 같이 관리 응답에 포함하지 않습니다. 다만 공개된 PIN 재발급 기능으로 참가자 계정을 복구할 수 있으므로 관리 화면을 접근 제한 수단으로 보아서는 안 됩니다. 참가자 페이지의 이름/PIN 로그인, 관리 API의 JSON/출처 확인, 분당 120회 관리 요청 제한, 테스트 전용 기능의 일반 모임 차단, 모임 코드 삭제 확인은 유지합니다. 이전 비밀번호/관리자 세션 관련 검증 기록은 당시 구현의 이력입니다.

## 2026-10-27 참가자 수 제한 해제

10~20명 범위를 제거했습니다. 서로 다른 이름 2명 이상이면 입력한 인원으로 모임을 생성하며 별도 최대 인원은 두지 않습니다. 명단 입력란의 기존 700자 제한도 제거했습니다. 개별 이름 30자와 API 요청 크기 한도는 유지합니다. 입력 중 인원수와 배정 전 전체 인원을 표시합니다. 2명은 서로에게 배정되며, 이때도 내 마니또/내 천사 대화방을 메시지 방향으로 분리합니다. 3명 이상은 기존 순환 배정으로 자기 배정·중복·맞교환을 방지합니다.

## 개인 초대 링크와 기기 등록

- 관리자에서 모임을 만들면 참가자별 **개인 초대 링크 복사**와 **전체 링크 복사**를 제공합니다. 링크는 해당 목록에만 표시되고 다시 조회되지 않습니다.
- 기존 모임은 참가자별 **개인 초대 링크 발급** 또는 **전체 개인 초대 링크 발급**으로 전환할 수 있습니다. 발급 확인 시 기존 기기와 이전 링크가 해제되지만 명단·배정·기도·편지 등 활동은 유지됩니다. 전체 발급은 모든 참가자에게 영향을 줍니다.
- 참가자가 링크를 누르면 초대된 이름이 표시됩니다. 이름을 확인하고 기기 이름(선택)을 적은 뒤 **이 기기로 참여하기**를 누릅니다. PIN·모임 코드·초대코드를 직접 입력하지 않습니다.
- 링크는 무작위 256비트 토큰으로 7일 유효하며 한 번만 등록할 수 있습니다. 토큰과 모임/참가자 식별자는 URL fragment에 넣어 웹 서버 요청 URL·Referer로 전송하지 않습니다. 등록 직후 주소에서 fragment를 지웁니다.
- 기기 자격증명은 별도로 생성한 무작위 토큰입니다. 브라우저에는 90일 HttpOnly·SameSite=Strict 쿠키(운영 Secure), DB 모임 JSON에는 해시만 저장합니다. 원본 토큰을 응답 본문·localStorage에 저장하지 않습니다. 초대 소비와 기기 해시 저장은 같은 버전 조건 갱신으로 처리해 동시 중복 사용을 방지합니다.
- 참가자당 한 기기 등록입니다. “기기”는 물리적 휴대폰 식별이 아닌 브라우저의 등록 정보이므로 다른 브라우저·새 기기·기록 삭제·90일 만료 시 링크를 다시 발급합니다. 링크 발급 시 이전 기기 자격증명을 즉시 해제합니다.
- 참가자는 **기기 등록 해제** 확인으로 자동 접속을 종료할 수 있습니다. 다시 참여하려면 새 링크가 필요합니다. 사용한 링크를 같은 등록 브라우저에서 다시 열면 기존 등록으로 자동 접속됩니다.
- 이전 PIN 로그인/join API는 410으로 종료됩니다. 이미 발급된 미만료 세션은 원래 만료까지 호환하고, 새 링크 발급/기기 해제 시 즉시 차단됩니다. 기존 PIN 해시는 이전 데이터 호환용으로만 남을 수 있고 PIN으로 새 로그인할 수 없습니다.
- DB schema migration은 필요 없습니다. 기기·초대 메타데이터는 기존 모임 JSON에 저장하며 새 계정/모임에만 적용되거나 링크 발급 시 전환됩니다. 기존 모임이나 실제 기기 등록을 배포 과정에서 임의로 초기화하지 않습니다.

관리 화면은 사용자 요청으로 공개되어 있으므로 누구나 참가자 링크를 재발급할 수 있습니다. 기기 등록은 입력 편의 기능이며 관리 화면을 접근 제한 수단으로 보아서는 안 됩니다.
