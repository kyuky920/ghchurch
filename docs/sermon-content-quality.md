# 청년부 말씀 자료 품질 개선

2026-10-27 적용. 기존 서비스의 주간 설교·3단계 질문·개인 메모를 유지하면서 원문 근거·녹취 검토·진행 보조를 보완했습니다. 기존 자료는 재생성하거나 일괄 수정하지 않습니다.

## 생성과 검토

1. 녹취 원문을 수정하지 않고 문단 ID를 붙입니다. 원문이 없으면 대지/요약, 그마저 없으면 성경 본문을 근거로 사용하고 자료의 종류를 구분합니다.
2. 중심 주제와 대지별 차이, 원문 비유·생활 장면·중요한 구분을 추출합니다. 발췌는 교정 전 원문과 일치해야 합니다.
3. 기존 핵심·전체 흐름·대지별 요약과 기본 7문항을 작성합니다. 각 요약과 질문은 실제 원문 문단 ID를 연결합니다.
4. 여는 질문 1개, 핵심 질문 표시, 실천 선택지 1~2개, 마무리 기도 초안을 추가합니다. 선택지는 질문 수에 포함하지 않으며 하나를 고르거나 스스로 정할 수 있습니다.
5. 별도 AI 호출이 원문과 생성 결과를 다시 대조합니다. 구조·발췌 검증과 의미 검토는 서로 다른 검사입니다. 원문 ID가 있다는 사실만으로 의미가 입증되지는 않습니다.
6. 원음 확인 필요나 심각한 검토 문제, 검토 호출 실패가 있으면 관리자가 확인하기 전까지 일반 목록과 익명 단건 조회에서 보류합니다. 관리자 화면에서 원문·교정 기록·검토 의견을 보고 저장하거나, 확인 완료 후 공개합니다.

독립 검토는 동일한 설정 엔진을 추가로 한 번 호출합니다. 생성 비용과 소요 시간이 늘며, 별도 AI 검토도 오류가 있을 수 있어 목회자의 검토를 대체하지 않습니다. 모델·엔진의 기본 설정은 변경하지 않았습니다.

## 설교를 듣지 못한 참여자와 마음 열기

- 설교는 중심 주제와 적용 방향의 근거로 유지합니다. 말씀 점검 질문은 함께 읽는 제공 성경 본문만으로 답할 수 있게 구성합니다.
- “목사님은”을 삭제하는 데서 끝내지 않고 질문·보조설명·참고 답안과 장절을 함께 수정합니다. 설교에만 있는 설명을 본문에 직접 기록된 답처럼 바꾸지 않습니다.
- 참여자용 질문·설명·답안의 설교 청취 전제 표현과 점검 질문의 빈 장절을 자동 검사합니다. 실제로 본문에서 답할 수 있는지는 독립 AI와 사람의 의미 검토가 필요합니다.
- 요약에서는 성경의 진술과 설교의 해석·권면을 계속 구분합니다.
- 마음 열기는 최근의 기쁨·마음 쓰이는 일 등 근황과 마음을 듣는 한 가지 질문으로 작성합니다. 원문 비유의 소품 사용 경험을 억지로 묻거나 특정 경험·고백을 전제하지 않습니다.

## 녹취 오류

- 녹취 원문 자체를 덮어쓰지 않습니다.
- 문맥과 반복으로 뒷받침되는 후보는 `context_supported`로 기록하며, 원음 확인을 완료한 것으로 간주하지 않습니다.
- 의미·신학·부정어·인명·장절이 불확실하면 `needs_confirmation`으로 기록하고 공개를 보류합니다. 프로그램은 적어도 부정·극성 변화가 확정 교정으로 기록되는 것을 거부합니다. 모든 인명·신학 오류를 자동 탐지한다고 주장하지 않습니다.
- ‘빛을 바라는/발하는’처럼 발음이 비슷하다는 이유로 전역 치환하지 않습니다. 명백하지 않은 것은 별도 원음 확인이 필요합니다.
- 성경 직접 인용은 제공한 본문과 대조하도록 지시합니다. 외부 장절을 모델 기억으로 확정 인용하지 않도록 하며, 모든 인용 문구를 프로그램이 자동 대조하는 것은 아닙니다.
- 교정 전 발췌·후보·이유·문단 ID를 `questions.meta.transcript_review`에 보존합니다.

## 저장 호환성

추가 자료는 기존 `questions.meta`에, 원문 근거는 요약과 질문 항목에 저장합니다. 새 DB 컬럼이나 마이그레이션은 필요하지 않습니다. 구형 배열/객체형 질문은 계속 읽을 수 있습니다. 관리자 편집 때도 보조자료와 근거를 보존합니다.

새 버전 자료를 편집하면 이전 AI/사람 검토로 수정 문안까지 승인된 것으로 간주하지 않습니다. 서버에서도 이전 확인을 취소하고, 관리자가 명시적으로 확인 완료 후 공개해야 합니다. 원문을 재등록하면 기존 방식대로 다시 생성 대기 상태가 됩니다.

## 로컬 검증

- `npm run test:sermon-content`: 실제 DB·외부 AI를 사용하지 않는 구조/발췌/교정/편집/공개 보류/API 테스트.
- 전체 테스트: `node --test tests/*.test.mjs`.
- 로컬 원고 시험: `node local-agent/sermon-materials-agent.mjs --input-file <설교입력.json> --dry-run --output-file <결과.json>`.

`--input-file`은 `--dry-run`에서만 허용하며 DB 클라이언트를 생성하지 않습니다. 그러나 실제 생성·검토를 요청하면 원고가 설정한 외부 AI 엔진에 전송됩니다. `--dry-run`은 외부 전송을 막는 옵션이 아닙니다. `--mock-file`은 외부 호출 없는 구조 시험 전용으로 `--dry-run`에서만 허용하고, 검토 미실행으로 표시합니다.

자동 테스트와 가상 자료를 사용하는 모바일·관리자 화면 확인을 수행했습니다. 이후 사용자의 명시적 전송 요청에 따라 실제 10월 25일 원고로 Codex 생성·독립 검토를 완료하고 읽기용 편집본을 별도로 작성했습니다. 이번 참여 방식 수정은 사용자 피드백을 반영한 편집이며 새 AI 독립 검토를 수행하지 않았습니다. 원음 확인 필요 항목이 남아 있어 운영 서비스에 게시하지 않았습니다. 한 사례만으로 일반적인 품질 향상을 단정하지 않습니다.

## 근거 문서

- [OpenAI 공식 구조화 출력 안내](https://developers.openai.com/api/docs/guides/structured-outputs): 형식을 맞추는 것과 내용의 정확성은 구분해야 합니다.
- [OpenAI 공식 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices): 구체적 과제와 실제 사례를 기준으로 평가하고, 사람의 판단과 함께 개선 효과를 확인합니다.

## 선택 항목 수정

관리자가 특정 질문이나 요약 부분을 지정해 로컬 Agent에 수정 요청할 수 있습니다. 설치와 실행, 수정안 비교·반영·공개 절차는 [로컬 Agent 안내](../local-agent/README.md#선택한-부분만-수정-요청)를 참고하세요. 변경은 별도 요청 테이블에서 초안으로 처리하며, 원고와 선택하지 않은 문안은 보존합니다.


## 명시적 운영 게시와 원음 미확인 기록

사용자가 운영 게시를 요청한 경우에도 원음 확인을 완료했다고 기록하지 않습니다. 원문 텍스트·제공 성경 본문 검토와 독립 검토를 통과하고, 남은 모호한 녹취 해석을 문안의 근거로 사용하지 않았다는 항목별 검토 기록을 갖춘 경우에 한해 `publication_review`로 게시 근거를 남깁니다. 이는 `human_review`나 원음 검증 기록이 아닙니다. 미확인 녹취 목록은 그대로 남으며, 내용·본문·원고를 편집하면 게시 검토 기록을 취소합니다. 근거가 불확실한 주장이 문안에 남으면 게시하지 않습니다.
